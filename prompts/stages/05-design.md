# Stage 5 — Design and wireframes

Using the approved features, requirements and architecture:

1. Ask about look and feel, references I like, accessibility needs, and target devices.
2. Write one wireframe file per screen at `planning/wireframes/S-<name>.md`: an ASCII sketch in a `text` block, then **Requirements**, **Elements**, **States** (empty, loading, error, success) and **Interactions**.
   (If the project has no UI, skip wireframes and say so; put CLI/API surface design in 05-design.md instead.)
3. Write `planning/05-design.md`: UX principles, screens & navigation table plus a mermaid navigation flow, visual design (typography, colour tokens, spacing, component library), API contracts (one block per endpoint or interface with request, response, errors, and the FRs it serves), and content & copy guidance.
4. Update the `Screens:` lines in `02-features.md` and re-emit it.
5. Revise until I approve.
